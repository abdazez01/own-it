# own-it v2.0: end-to-end run, no-dashes test, browser check

Date: 2026-10-17. Scratch project: `.superpowers/sdd/2026-10-17-own-it-v2/e2e/trip-app` (copy of `fixtures/trip-app`, git init, local user config). Wrapper `e2e/o.sh <cmd>` = `cd trip-app && node own-it/scripts/own-it.mjs <cmd>`. I followed `SKILL.md` and its references as written, playing both runtime Claude and the player (events POSTed with curl using the `serve.json` token; the browser pane and a real Chrome were used for the page).

## Verdict

**FAIL (one blocking bug, two serious).** Every helper command worked and the loop finishes, but two bugs break the real player path:

1. **B1 (blocking).** A real result sent by the page is rejected by `collect` for 5 of 6 games (no `text` field). Reproduced with the real page, not only curl.
2. **B2 (serious).** Round data built before the page loads is never shown. After any page load/reload, pre-built rounds are invisible until the file changes again.
3. **B3 (serious, design).** The canonical cross-role flow cannot be a quest (reachability check), and the docs do not explain it.

Counts: 3 serious bugs, 5 minor bugs/nits, 10 doc ambiguities. `tests/no-dashes.test.mjs` passes (1/1). No dashes found in assets, references or SKILL.md.

## Bugs

**B1 (blocking). The page's real result payload fails `collect` validation.**
- Repro: play any quiz (also screen-tour, guess-the-screen, quests, whiteboard, which build their payload via `kit.finish`) to the end in the page. The event written to `.own-it/inbox/*-result.json` was `{"type":"result","id":"trips-quiz-9","game":"quiz","mode":"practice","submittedAt":"...","got":4,"of":5,"missed":["3"],"hintsUsed":0}`. Then `collect trips-quiz-9` prints `own-it: no answer file for "trips-quiz-9" in C:\Users\...\Downloads. Submit again, or set the download folder`.
- Cause: `own-it/scripts/lib/validate.mjs:59` (`ANSWER` requires `text`) rejects it; `cmd-collect.mjs` `inboxResult` (about line 25-37) swallows the validation failure, falls through to Downloads and reports a misleading error. `own-it/assets/engine/gamekit.js:109-115` builds the payload with no `text` (only boss-battle adds `text` through `extra`), and `assets/core.js:249` (`payload()`) is not used by these games. Tests pass because `tests/collect.test.mjs:18` fixtures include `text: {}`.
- Fix options: add `text: {}` and `challenges: []` in `kit.finish`, or make `text` optional in `ANSWER`; and have `collect` say `invalid answer` for an inbox hit that fails validation.

**B2 (serious). Pre-built rounds never load on a fresh page.**
- Repro: build rounds, `serve`, open the page. Home shows every rec as "Ask Claude" (not "Ready"), and clicking Quiz shows "Claude is building your Quiz round" and sends a `pick` although `trips-quiz-1` exists. `window.OWNIT_ROUNDS` is empty after load. Touching `.own-it/data/*.js` (or rebuilding) loads them within the poll interval, and then cards show "Ready".
- Cause: `own-it/assets/game.html:34-43` has no `<script src="data/...">`, and `own-it/assets/engine/link.js:72-76` baselines `known` on the first poll without injecting, so only later changes are injected. Same for feedback data. A reload also drops everything again.
- Impact: contradicts `onboarding.md` step 5 ("Pre-build rounds for them with `build-round`"); each first click costs a pick round trip, and a reload during a session loses all loaded rounds.

**B3 (serious, design). A quest cannot span roles.**
- Repro: quest `flow:f-cancel, start:s-trip, objectives:[el-cancel, el-approve]` -> `own-it: objective el-approve not reachable from start` (`cmd-build-round.mjs` `checkQuest`). Reachability follows `element.goes` between surfaces; the cancel button goes to an endpoint (`s-cancel`), and the manager screen is not linked from it. The flow the fixture is built around (driver cancels, manager approves) therefore cannot be a quest. I worked around it with a manager-only quest.
- Neither `games.md` nor `extraction.md` says quests are single-role-reachable chains or how to model a role switch ("Switch role" exists in the page).

**B4 (minor). `apply` of a boss round with 3 solid does not clear.** `apply trips-boss-battle-5` with q1,q3,q5 solid, q2 partial, q4 miss -> `ratio 0.6`, `cleared []`. `bosses.md` says passing needs "at least 3 solid"; the ratio also matters and the doc does not say how (D8).

**B5 (minor). Leaked quest intro modal.** After opening Quests and then calling `OwnIt.router.go('home')` or another game with the intro open, the "QUEST" modal stays on top of Home and the next game. (Reached programmatically; a user hits Back first. Still, the router should clean up on destroy.)

**B6 (nit). Console error on every load:** `Unrecognized Content-Security-Policy directive 'navigate-to'` (Chrome). Source `own-it/assets/engine/screenhost.js:10` (screen copy iframe CSP). Harmless but shows in the console.

**B7 (nit). Departures "Next" column lists unplayable games** ("Design Duel, 3am Pager" for a zone where the playable rung is boss; "Memory Match, Quiz" for access). Those tiles say "Coming in a later update". `home.js` next-suggestion should skip games not built at this stage.

**B8 (nit). Whiteboard card labels wrap mid-word** at 375 px (`POST /trips/:id/ca / ncel`). Long route labels need `overflow-wrap:anywhere` only as a last resort, or `word-break` at slashes.

## Doc ambiguities

- **D1.** `onboarding.md` step 5: "run `build-recs`". It needs a file: `build-recs .own-it/recs.json` (usage error otherwise).
- **D2.** `games.md`: "Quiz, screen-tour and guess-the-screen need `answer` on every entry". It never says what an answer is for screen-tour kinds. From the code: `chain` needs `element` plus 2-4 `choices` that are model ids, answer one of them; `find` has no choices and the answer is an element id; `role` has free-text choices and the answer is one of them. Guess-the-screen `choices` are surface ids, answer one of them. I had to read `cmd-build-round.mjs`.
- **D3.** `games.md` "Zones with 3+ screens" for guess-the-screen: I built copies for only 2 screens but 7 surfaces exist; unclear whether the count is model surfaces or built copies (a third screen without a copy was accepted; the page falls back).
- **D4.** `grading.md` "`apply <id> --text ...`" and `examples.md` `apply ... --got 8 --of 10` suggest `--got/--of` for any game; for rounds it is rejected (`--got/--of only apply to words and map missions`). A round `apply` takes no flags. Not stated.
- **D5.** `rungs.md` "Fogged zone: ... one `map` mission with `refresh:true`" fails when map is not cleared (`refresh needs a cleared rung`). I had to clear map first.
- **D6.** `bosses.md` / `onboarding.md`: "write `build-feedback <round>` with `{grades:{q1:"solid"}}` for that key". `build-feedback` replaces the file, so q1 vanished when q2 was written (`feedback-<round>.js` held only q2). Runtime Claude must resend all grades so far; the doc says "that key". (The page may merge; I did not test it.)
- **D7.** `onboarding.md` step 6 says run `open <url>`; this launches the user's browser. In an automated run I needed `OWNIT_NO_OPEN=1`; not documented in the skill.
- **D8.** `bosses.md` "passing needs board >= 70% ... and at least 3 solid": the practice result printed `ratio 0.6, cleared []` with 3 solid; scoring weights of partial are not given.
- **D9.** `grading.md` Challenge: "Resolve before `apply`; it runs once." A challenge can arrive after the round was applied (page sends it from the report card); the doc has no path for that.
- **D10.** `extraction.md` caps "At most 30 reads", "at most 80 items" are fine, but the model-extractor prompt asks for `does` on every `element` and "goes (surface id it leads to)"; it never tells the extractor that `goes` drives quest reachability (B3), so an honest extraction (button -> endpoint) yields a model that cannot make a cross-screen quest.

## Browser findings

The built-in browser pane (`mcp__Claude_Browser__*`) reached the serve URL and rendered the page, but its pane is a ~400x60 strip: screenshots at emulated widths are unreadable and `resize_window` could not go below 500 px innerWidth. I used it for load, console (0 messages) and overflow checks (`scrollWidth` 1265 = `clientWidth` 1265 at 1280), then repeated the checks and took readable screenshots in a real Chrome (chrome-devtools MCP, device emulation) at 375, 768, 1280, 1920. Check: for every element, `right > clientWidth` or `left < 0` (excluding fixed, canvas, and elements inside an overflow container).

| Width | Home | Quiz | Quests | Whiteboard | Screen tour | Guess | Boss | Console |
|---|---|---|---|---|---|---|---|---|
| 375 (mobile+touch) | no overflow; Departures table scrolls inside its own container | ok | ok (intro modal fits, objectives stack under screen) | ok, label wraps mid-word (B8) | ok | ok | ok | CSP navigate-to only |
| 768 | ok | ok | ok | ok | ok | ok | ok | same |
| 1280 | ok | ok | ok | ok | ok | ok | ok | same |
| 1920 | ok (content centered, max about 1440) | ok | ok | ok | ok | ok | ok | same |

`scrollWidth` equals `clientWidth` (or the viewport minus a 15 px scrollbar) in every case; zero stray elements. Quiz at 1280 is a 580 px card left-aligned in the content area with empty space on the right (works, looks unbalanced).

Quiz played by clicking: question 1 answered by clicking the first option, then the other four by scripted clicks (including Next and See result). Right answer showed `+10 XP` and the why line, confetti played, the result card listed the missed question, and the `result` event reached the inbox (B1 payload above).

Console messages across the session: only the CSP `navigate-to` error (B6) and a Chrome form-field-without-name issue (x3, informational).
